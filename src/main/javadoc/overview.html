This library provides OpenTelemetry integration for Soklet by supplying OpenTelemetryMetricsCollector, an implementation of MetricsCollector, and OpenTelemetryLifecycleObserver, an implementation of LifecycleObserver.

Wire it into SokletConfig via .metricsCollector(...) and .lifecycleObservers(...) using either an OpenTelemetry instance, or via lower-level Meter and Tracer instances.

By default, standard HTTP metrics use OpenTelemetry Semantic Convention names, while Soklet-specific metrics are emitted for concepts such as Server-Sent Events and MCP. HTTP, streaming-response, and SSE spans use Soklet's parsed HTTP W3C trace context as the remote parent when available; admitted MCP request spans use only validated trace context carried in MCP metadata.

Version 2.0.0 targets provided Soklet 4.0.0. The prior soklet-otel 1.3.1 release targets Soklet 3.5.1.

Builders do not read or initialize GlobalOpenTelemetry. Without an explicit SDK, meter, or tracer, they resolve the global only when build() is called. Both integrations use the library's packaged Implementation-Version as the default instrumentation version when available; an explicit instrumentation version overrides it.

HTTP spans correlate by the original per-dispatch request instance, not its configurable ID. The simulator copies each dispatch so callers may concurrently reuse the same input request. Wrapper/interceptor replacements do not change that identity or the HTTP parent trace context; routing still uses the effective request. Streaming spans wait for both handling completion and stream termination, in either order. HTTP 5xx responses without a throwable use the decimal status as error.type; throwable-free stream failures use the lower-snake termination reason.

soklet.server.request.throwables is a Counter with unit {throwable}. It counts observed throwables, not failed requests: two throwables increment the counter by two. In 2.0.0, metrics and spans share the soklet.server.type vocabulary: http (including streaming HTTP), sse, or mcp. Migrate HTTP metric filters from standard_http to http and SSE span filters from server_sent_event to sse. HTTP spans retain http; SSE metrics retain sse, and MCP retains mcp across both signals.

The HTTP metric-label change affects Soklet connection, request-acceptance, request-read-failure, and transport-failure counters under both naming strategies, including SEMCONV. Request-handling and response-write metrics (including soklet.server.request.throwables) carry soklet.server.type only under SOKLET. Standard HTTP instrument names, semantic-convention attributes, and url.scheme=http do not change; this migration adds no attributes to metrics that omit them.

Framework-produced dimensions are bounded to registered endpoint paths, recognized methods or <unrecognized>, fixed lower-snake enum values, and protocol-error codes -32700,-32600,-32601,-32602,-32603,-32020,-32021,-32022,-31999,-31998. Manually constructed events remain application-controlled, and OpenTelemetry SDK views/readers/exporters own their retention. For framework-produced events, the integration adds no dedicated attributes for request or payload data, header names or values, request IDs, trace or parent IDs, trace-correlation tokens or key IDs, tracestate, baggage, throwable material, or error.type. Applications control values placed in public dimensions by manually constructed events; those values can contain sensitive text, so applications own both their confidentiality and cardinality. The integration does not promise core snapshot/reset/filter, configured-zero, or cross-instrument atomicity semantics.

MCP request spans in 2.0.0

Compared with 1.3.1, MCP spans rename rpc.system to rpc.system.name and soklet.mcp.endpoint.class to soklet.mcp.endpoint; the endpoint value is now the registered path rather than a Java class name. The old long-valued span attribute rpc.jsonrpc.error_code becomes decimal-string rpc.response.status_code. Update trace queries and attribute-type expectations. The protocol-error metric still uses long-valued rpc.jsonrpc.error_code.

When an application installs OpenTelemetryLifecycleObserver, the default-on SpanPolicy.recordMcpRequestSpans() creates one SERVER span for each admitted MCP request or notification. The span starts with semantic handling and remains open through the exact client-visible terminal outcome, including request-stream and subscription lifetimes. Preadmission failures have no span, and there is no separate MCP session, request-stream, or subscription span.

The only remote-parent source is validated McpRequestContext.getTraceContext() metadata. Its trace ID, parent ID, flags, and tracestate are preserved. Missing or invalid metadata yields a root span; physical HTTP trace context, current OpenTelemetry context, links, and baggage are never fallback parents. Raw trace identity remains parent/span identity and is not duplicated into attributes or events.

The default name is MCP <method>. Both it and rpc.method accept the exact bounded live vocabulary server/discover, tools/list, tools/call, prompts/list, prompts/get, resources/list, resources/templates/list, resources/read, subscriptions/listen, notifications/cancelled, tasks/get, tasks/update, and tasks/cancel; every other value becomes <unrecognized>, and no rpc.method_original is emitted. A custom naming strategy receives the full context, so the application owns custom-name confidentiality and cardinality.

MCP tracing migration

The legacy soklet.mcp.sessions.* and soklet.mcp.session.duration instruments and observer callbacks didCreateMcpSession, didTerminateMcpSession, didEstablishMcpSseStream, and didTerminateMcpSseStream are removed. The SpanPolicy.recordMcpSessionEvents and recordMcpSseStreamSpans controls and their builder setters are also removed. recordMcpRequestSpans remains with modern admitted-request semantics. The default SpanNamingStrategy.mcpRequestSpanName(McpRequestContext) replaces the old request-shaped method; custom strategies do not need to implement it. The legacy MCP-SSE naming method is absent, and old MCP naming overrides are no longer invoked.

Relative to released 1.3.1, the verified 2.0.0 public API delta is 13 removals and 4 additions. The four additions are the modern metric callback, modern request start and finish callbacks, and context-shaped naming method; the 13 removals include the two legacy session-policy controls named above. The 2.0.0 release verification contract runs the complete module and Javadoc build against exact Soklet 4.0.0.
